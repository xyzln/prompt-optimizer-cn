# 示例 1：周报写作（办公场景）

## 原文（~120 tok，按 o200k 汇率估算）

> 那个，帮我写个周报呗，这周的话干了挺多活的，主要就是项目推进了不少，然后大大小小的会开了好几个，bug 也改了特别多，烦死了，我们老板每周都要看这个，你帮我写得正式一点、专业一点，但是也别写太长了，他没耐心看，哦对了数据别瞎编啊，改了多少写多少

## 拆解

| 要素 | 内容 |
|---|---|
| 目标 | 写本周周报 |
| 输入 | 用户口中的素材（项目/会/bug，无具体数字 → 标「?」） |
| 硬约束 | 正式；别太长；数据不虚构 |
| 交付物 | 周报正文 |
| 成功标准 | 上级能快速看完（≤300 字） |
| 隐含前提 | 读者 = 直属上级；「别太长」需量化 |

## 框架

形态：单轮问答 ｜ 表达：目标 + 结构 + 素材 + 禁区（写作类必须给结构，否则模型自由发挥）

## 压缩稿（~65 tok，省 ~46%）

```
写本周周报：读者=直属上级；正式；≤300字。
结构：进展｜数据｜风险｜下周计划。
素材：项目A联调完成；修bug×3（支付回调）；评审会×2。
禁区：不虚构数据，数字照实。
```

## 要点

- 「烦死了」「他没耐心看」→ 删情绪，提炼为硬约束「≤300字」
- 「别瞎编」→ 正向禁区「不虚构数据，数字照实」——写作场景最常见的翻车点
- 素材列表化（×3/×2），模型只需组织语言不用编造
- 原文缺具体数字 → 压缩稿里填示例数并提示照实替换（或先反问确认）
