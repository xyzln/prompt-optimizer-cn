# 示例 1：口语化性能优化需求

## 原文（~150 tok，按 o200k 汇率 ≈1/字估算）

> 帮我看看这个项目吧，就是我现在这个代码跑起来特别慢，我也不知道为啥，你帮我优化一下，最好是快点，哦对了我用的是 Python，数据大概有几十万条，就是 pandas 处理的那个脚本，每天早上跑报表用，现在要等好几分钟，老板催了，能不能搞到十几秒这种水平啊，谢谢啦

## 拆解

| 要素 | 内容 |
|---|---|
| 目标 | pandas 报表脚本提速到 <20s |
| 输入 | ~/report.py |
| 硬约束 | 不改输出格式；pandas 2.x |
| 交付物 | 瓶颈分析 + 优化 diff |
| 成功标准 | 运行时间 3min+ → <20s |
| 隐含前提 | 可 profile、有测试数据（存疑 → 确认） |

## 框架

形态：单轮问答（一次性小任务）｜表达：目标 + 路径 + 约束 + 禁区

## 压缩稿（~75 tok，省 ~50%）

```
优化 ~/report.py（pandas，~50万行，每日报表）：运行 3min+ → 目标 <20s。
先 cProfile 定位瓶颈，再给优化 diff。
禁区：不改输出格式；pandas 2.x。
```

## 要点

- 「最好是快点」「老板催了」「谢谢啦」→ 删（无信息）
- 「好几分钟」→「3min+」；「十几万秒这种水平」→「<20s」（模糊词量化，防止模型自由发挥）
- 「数据大概有几十万条」→「~50万行」（规模决定优化策略，必须保留）
- 交付物明确为「瓶颈分析 + diff」，避免模型直接重写整个文件
