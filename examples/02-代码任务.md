# 示例 2：嵌入式代码任务（含执行框架推荐）

## 原文（~140 tok）

> 我们有个 STM32 的智能车项目，电机 PID 调得不太好，车在直线上会轻微画龙，你帮我把 PID 参数调一下或者改改控制逻辑，让车走直线稳一点，代码在 SmartCar 那个文件夹里，你看着办吧，应该不难

## 拆解

| 要素 | 内容 |
|---|---|
| 目标 | 消除直行画龙（稳态振荡） |
| 输入 | SmartCar/ 工程 |
| 硬约束 | 不动引脚定义；STM32F4 |
| 交付物 | 修改 diff + 调参说明 |
| 成功标准 | 直行偏移 < 5cm/m（? 需确认有无实测条件） |
| 隐含前提 | 「画龙」= 稳态振荡而非偶发扰动；双电机差速 |

## 框架

形态：**subagent**（代码检索量大，隔离上下文，主线程只收结论）｜表达：目标 + path + 约束 + 禁区

## 压缩稿（~80 tok，省 ~43%）

```
修智能车直行画龙：SmartCar/（STM32F4，双电机差速 PID）。
症状：直行稳态振荡。
定位 motor.c/pid.c → 调参或改控制律；目标直行偏移 < 5cm/m。
给 diff + 调参依据。禁区：不动引脚定义。
```

## 要点

- 「你看着办吧，应该不难」→ 删（无信息，且易诱导模型草率动手）
- 「电机 PID 调得不太好」→ 症状描述「稳态振荡」（振荡/静差/超调对应不同治法，说症状不说猜测）
- 「轻微画龙」→ 量化为「偏移 < 5cm/m」作为验收标准
- 文件夹名补全为路径，指明代数级文件（motor.c/pid.c）减少检索轮次
